# 安全责任矩阵与部署契约（讨论稿）

本文用于讨论 wuli3、业务应用、网关和基础设施的安全职责。现状依据当前仓库源码；建议契约尚未代表实际部署已满足，也不代表新增能力已实现。本文不修改运行行为，不指定 Higress 插件或 K8s 配置；具体实现需结合版本、网络拓扑和认证方案验证。

## 设计原则

哪一层掌握作出判断所需的信息，就由哪一层负责该判断。入口尽早限制恶意流量；服务仍负责业务授权和资源消耗边界。内网可达、身份字段格式合法、请求存在上下文，均不能单独证明调用方有权限。

wuli3 提供安全默认值、稳定的集成边界和可验证的通用机制；应用定义业务策略；平台维护入口与工作负载隔离。先明确责任，再判断是否需要独立 security starter。

## 责任矩阵

| 风险或能力 | 主要责任方 | wuli3／应用的边界 |
| --- | --- | --- |
| 大流量 DDoS | 云边缘、高防或上游流量清洗服务 | 应用限流不能替代入口带宽保护 |
| 入口滥用、扫描、通用恶意请求 | 网关按需配置限流、WAF、大小和超时限制 | 应用仍需参数校验；WAF 不替代安全编码 |
| 网络暴露、工作负载权限、密钥 | K8s／平台团队 | 明确允许的调用路径；验证实际网络策略生效；凭据不进入源码和日志 |
| 身份认证 | 选定的网关或应用认证组件 | wuli3 消费经过验证的身份；传播和解码本身不承担认证 |
| 对象级授权、租户隔离 | 业务应用 | 查询、更新、导出和异步任务均检查权限；不能仅依据前端传入的用户或租户 ID |
| 分页、批量、上传、解析和下游调用成本 | 应用与入口共同承担 | 网关限制入口总量；应用限制单次操作成本、并发和执行时间 |
| SQL 注入、SSRF、文件路径越界 | 应用及相应基础组件 | 参数化查询；外部 URL 和文件路径做语义约束；网络出站限制作为补充 |
| XSS、CSRF、CORS | 前端与应用，网关可协助统一策略 | 按页面输出与凭据携带方式配置；CORS 不是认证，也不能阻止非浏览器调用 |
| 错误泄露、敏感日志 | wuli3 机制与应用字段策略 | 内部诊断与公开响应分离；脱敏不等于授权，也不能代替字段最小化 |
| 重放、重复提交、业务刷取 | 业务应用 | 按操作定义幂等、时效和额度；requestId 不能充当授权凭证或通用防重放机制 |
| 依赖漏洞和镜像更新 | 项目维护者与发布平台 | 版本治理、漏洞修复与发布验证形成闭环 |

## 建议部署契约

### 客户端 → 网关

- 网关清除外部输入的保留身份头 `X-Principal-Type`、`X-Principal-Id`、`X-Principal-Name`，认证成功后根据可信结果重新写入；匿名请求也不能保留外部提供的身份头。
- 对重复头、大小写变体和代理链转发使用一致规则，避免网关与服务解释不同。
- 外部传入的租户选择只是请求参数；只有在验证主体与租户关系后才能成为授权依据。当前内置身份传播字段不包含租户契约。
- 公共路由和受保护路由明确区分；缺失、过期或无效凭据不能被无意降级成可访问受保护资源的匿名请求。

### 网关 → 服务

- 使用默认身份头解析器时，所有能到达业务端口的路径都必须满足可信上游前提。仅关闭公网入口不足以约束其他内部工作负载。
- 平台维护允许的调用方和端口范围，阻断绕过网关的非授权调用；若存在其他内部调用方，也需明确其身份转授权限。
- 传输保护和调用方身份校验按部署方案选定，例如受控网络配合工作负载认证，或服务验证面向自身的凭证。仅“同处一个集群”不构成信任证明。
- `trusted-proxy-cidrs` 仅配置实际代理来源范围，并结合真实 peer 地址和代理链验证客户端 IP；它不能替代上述身份来源控制。
- 直接接收外部请求的服务替换 `AuthContextResolver`，从经过验证的认证结果建立上下文。使用安全框架时，要验证认证执行在读取身份之前，不能仅注册 Bean 就假定顺序正确。

### 服务 → 内部 HTTP／RPC → 数据层

- 区分工作负载身份与最终用户身份：谁在调用、代表谁调用、允许做什么，不能合并成一个可信 Header 判断。
- 下游基于已验证的调用方和业务规则授权；内部服务能够调用接口，不代表能够任意声明用户或 `SYSTEM` 身份。
- 查询和修改校验对象归属及租户范围；缓存键、导出任务和后台任务保持相同隔离规则。
- 上下文传播只传必要信息；线程或异步上下文恢复正确，不代表长时间任务中的权限仍然有效。

### 服务 → 第三方

- 使用不传播内部身份的客户端；不能把默认安装上下文拦截器的客户端直接复用于任意第三方地址。
- 外部可控 URL 需限制协议、目标和重定向行为，并结合 DNS 解析、网络出站策略防止访问内部资源。
- 对超时、响应大小和并发设置边界；不在日志中记录凭据或完整敏感响应。

## 优先讨论的决策

| 优先级 | 决策 | 建议方向 | 尚需确定的信息 |
| --- | --- | --- | --- |
| P0 | 身份头信任是否继续默认启用 | 倾向显式启用；未启用时不从外部 Header 恢复身份，受保护接口仍由认证／授权组件拒绝匿名访问 | 是否所有业务服务都只接收可信网关／内部调用；现有使用方的迁移成本 |
| P0 | 内部与外部 HTTP 客户端如何区分 | 明确拆分用途，让身份传播绑定可信目标；避免全局自定义配置误覆盖所有客户端 | 当前第三方调用方式、服务发现方式、重定向需求 |
| P0 | 谁验证认证凭据、谁可转授身份 | 明确一种入口认证模式及每条内部调用路径的来源校验 | Token／Session 方案，网关与工作负载认证方式 |
| P1 | 租户信息如何建立与传递 | 先定义主体与租户关系、切换语义和数据隔离，再决定扩展上下文 | 是否多租户，管理员跨租户操作需求 |
| P1 | 资源限制与审计基线 | 建立各层限额与敏感操作审计要求 | 流量规模、上传需求、批量接口和数据保留要求 |

以上是建议，尚未决定或实现默认行为变更。无需先创建通用“防攻击 Filter”，也不建议统一用字符串替换处理 SQL／XSS。

## 契约验收场景

| 场景 | 预期结果 | 验证责任 |
| --- | --- | --- |
| 外部伪造任意 `X-Principal-*`，包括重复头 | 不能改变服务识别的主体；匿名请求不能获得伪造身份 | 网关与服务联调 |
| 未授权工作负载直连 HTTP／RPC 端口 | 在网络或调用方认证边界被拒绝 | 平台与服务联调 |
| 已认证用户访问其他用户／租户的对象 | 查询、修改、导出均不返回或变更未授权数据 | 业务集成测试 |
| 来源不可信但携带转发 IP 头 | 不把伪造值作为可信客户端 IP | Web 定向测试与部署验证 |
| 服务请求第三方，或发生跨目标重定向 | 不发送内部身份字段 | 客户端集成测试 |
| 超大请求、过大分页、慢下游 | 被相应边界限制；不造成无界内存、线程或连接占用 | 网关与应用压力验证 |
| 受保护接口缺失／无效身份 | 请求被拒绝；不会仅因成功创建调用上下文而放行 | 认证与授权集成测试 |
| 内部异常抵达公开出口 | 不泄露内部诊断、凭据或敏感字段 | 错误边界与日志验证 |

文档阶段完成标准：责任、当前前提、待决策项和验收场景可评审。代码阶段需另行确定选定方案、兼容迁移和对应回归测试；部署阶段需在实际环境取得验证证据。

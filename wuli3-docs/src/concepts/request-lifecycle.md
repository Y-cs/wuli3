# 请求生命周期

一次成功请求不等于每个安全和一致性问题都已解决。Wuli3 把机制拆成几个阶段，让应用能为每个阶段补齐自己的事实。

## 入口：先建立信任

默认 Web 解析器适用于可信网关已经认证并重新注入主体字段的内部 HTTP。它不会验证 Token 签名，也不会阻止服务被绕过网关直连。公网入口或其他认证方案应实现 AuthContextResolver，并用集成测试确认认证执行发生在读取主体之前。

## 上下文：只保存可传播的调用信息

请求标识、来源 IP、主体和权限版本可以进入上下文。线程池、虚拟线程和消息消费都必须显式恢复并在退出时还原。上下文传播不会延长权限有效期，也不会替代对象归属检查。

## 授权：功能许可不等于对象许可

权限目录描述“能执行什么动作”；应用仍需检查“能作用于哪个对象、租户和状态”。权限加载器、缓存和撤权策略由应用或权限系统提供。

## 用例：一次提交的事情一起提交

完整用例由 app service 组织。若创建订单需要写订单、扣库存和记录事件，就应在明确的事务或可靠消息方案中定义一致性，不要让 Controller 连续调用几个看似独立的 Service。

## 输出：按协议投影可见性

内部错误可以带诊断信息；公开响应只能输出符合可见性策略的字段。资源链接转换、敏感字段脱敏和响应包装是输出边界的职责，不能反向改变领域状态。
